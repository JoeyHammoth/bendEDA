# `law lint` and `law mutate`: rules L001-L015 and the mutation gate

Issue #10, Phase 0.8. Two commands, both of which fail for reasons a reviewer can
read: `lint` judges the law *set* as metadata and text, and `mutate` supplies the
evidence rule L006 needs by asking the real checker which laws notice a changed
model.

## Why the report has notes as well as findings

Three rules cannot be evaluated without inputs the package may not carry: L004
needs the full requirement list, L006 needs a mutation report, L014 needs
declared hashes. The linter appends a note when it skips one:

```text
law lint: note: L006 not evaluated: no mutation report was supplied
law lint: note: L004 not evaluated: the manifest declares no `requirements` list
```

A clean report means "every applicable rule ran and found nothing". It does not
mean "no rule had anything to say". The alternative — silence — is the failure
mode this programme studies, one layer up from the checker.

## Rules

| Rule | Checks | Deliberately not |
|---|---|---|
| L001 | a law with a proposition hypothesis, or in class `L-FUNC`/`L-REFN`, has a witness | whether the witness reaches the state (that is review) |
| L002 | law names in the file and manifest are the same set | that they match by id as well as name (L008) |
| L003 | every non-`L-NEG` law names at least one requirement | that the requirement is a good one |
| L004 | every declared requirement is covered by a law or declared conformance-/oracle-only | runs only when the manifest lists its requirements |
| L005 | a hypothesis that is a false closed equation (`{0n == 1n : Nat}`) | semantic unsatisfiability in general |
| L006 | a law killed by no mutant in the supplied mutation report | runs only with `--mutation` |
| L007 | `@unsafe`, a `def name?`, `?TODO`, `TODO` in a checked file | the full PEH list, which is issue #11 |
| L008 | `<task>_<class letter><nn>_<slug>` from the manifest id | taste in the slug |
| L009 | duplicate or alpha-equivalent claims (parameters renamed positionally) | equivalence up to rewriting |
| L010 | a referenced `X.y` is defined in the package or exported by Base | whether the abstraction map renames it; `abs.yaml` is not parsed yet |
| L011 | class `L-SAFE`/`L-FUNC`/`L-REFN` has a translation or a declared reason | whether the translation is faithful (that is `tf run`) |
| L012 | priority is `core`, `important` or `extended` | whether the tier is right |
| L013 | more than one `==` in one claim | genuine logical conjunction; it is a heuristic and says so |
| L014 | declared artifact hashes match the files | whether the artifact should be locked |
| L015 | `provenance.yaml` exists and its hashes match | the truth of `authored_by` or the attested reads |

## L006 is the connection between the two commands

`law mutate` writes a report with a `laws` map (`killed_by`, `total`); `lint`
reads it with `--mutation`. A law that survived every mutant is reported as L006,
which is the "model-insensitive law" defect from Appendix G.10. This is why the
commands exist as a pair: a linter alone can only guess at that defect.

## Mutation: how a kill is attributed

Bend 2.0.40 prints only the first failing law, and `import model` is rejected:

```text
expected : an import ('import Base', or 'import <path> as <Name>')
observed : 'import model'
```

So `law mutate` inlines the mutated model ahead of each law, followed by the law's
proof and the proofs it calls (a transitive dependency closure over named blocks),
and runs the checker once per law per mutant. Defaults are LA3's: at least 20
mutants, kill rate at least 0.9, and no law surviving every mutant. Exit 3 means no
checker or no mutable site — nothing was measured.

The catalogue has two halves, because a model can be all table and no arithmetic:

- **Arithmetic edits**: 15 well-typed operator swaps (`U32.add`↔`U32.sub`,
  `Word.and`→`Word.or`, `Bool.and`↔`Bool.or`, `Nat.add`↔`Nat.sub`, comparison
  variants, …) plus a literal bump on arithmetic lines.
- **Table edits**: exchange the bodies of two sibling `match` arms that bind the
  same names (a `Level` match is the common case), and replace a nullary
  constructor with another of its declared type (`Half{}`→`Full{}`,
  `False{}`→`True{}`). Constructor declarations and `case` patterns are never
  edited, so the result still parses; arms whose bound names differ are never
  swapped, so the result still typechecks.

A law file without its proof also prints `SOME PROOFS FAIL`, with `1 TODO found`.
That is an incomplete file, not a refutation, so it is recorded as an **error**: a
package that keeps laws and proofs in separate files must be mutated with `--laws`
pointing at the composed file, and a run whose laws are unproved measures nothing.

Cost scales as mutants × laws compiler runs, so `--max-mutants` caps a run.

## Evidence

```console
$ bendeda law lint tests/fixtures/law_packages/defective \
    --mutation tests/fixtures/law_packages/defective/mutation.json
law lint: 1 package(s), 12 law(s), 17 finding(s) (L001x1, L002x2, L003x1, L004x1,
  L005x1, L006x1, L007x1, L008x1, L009x1, L010x1, L011x1, L012x1, L013x1, L014x1, L015x2)
$ echo $?
1
```

The fixture seeds one defect per rule; `tests/test_law_lint.py` asserts the set of
fired rules is exactly `set(RULES)`, so a rule that stops firing fails the test. A
second, generated package is clean and must produce zero findings — a linter that
refuses everything would pass the defective fixture and fail that one.

```console
$ bendeda law mutate tests/fixtures/law_packages/toy_mutation --local \
    --min-mutants 2 --min-kill 0.5 --max-mutants 8
mutant  line  killed by        survived / errors
m001       8  toy_s01_step     -
m002       8  toy_s01_step     -
law mutate: 2 mutant(s), 2 killed by at least one law, kill rate 1.00
```

The live path is exercised in `tests/test_law_mutate.py::TestLiveMutation` when
`BENDEDA_BUN` and `BENDEDA_BEND_CLI` are set, and in CI's `vector-path` and
`bend-image` jobs.

## Limits

- L005 and L013 are syntactic; L007 is a subset until the PEH list lands (#11);
  L010 does not read `abs.yaml` yet, so an abstraction-map alias would be flagged.
- Mutation covers `model.bend` only, and the catalogue is operator-level. It does
  not rewrite guards or rearrange state, so a law insensitive to *structure*
  rather than arithmetic can survive.
- The 20/0.9 defaults are the protocol's, not a property of the tool; a task may
  pass other values, and the report records which were used.
- The defective fixture is lint-only. Two of its defects only exist at the text
  layer, so compiling it would test something else.
