# toy_counter corpus — gate sensitivity and specificity (LA4)

A corpus for `bendeda gate calibrate`. Every entry is the same reference submission
(`experiments/fixtures/toy_counter`) with one file replaced, so a bug is a one-file diff
against a design that already passes, and one model, manifest and plan judge all of them.

| Kind | What it is | Count |
|---|---|---|
| `correct` | structurally different implementations of the same contract | 3 |
| `mutant` | one small edit to the reference RTL | 3 |
| `seeded` | a plausible implementation defect a person would write | 3 |

`corpus.json` names the base, the gate set and the entries. `mutant` and `seeded` are
reported apart because the design reports GS separately for mutants and seeded bugs: a
gate that catches only the hand-written half is not calibrated, it is lucky.

```console
$ bendeda gate calibrate --corpus experiments/corpus/toy_counter
gate calibrate: toy_counter from experiments/corpus/toy_counter, gates trace
  correct/golden                     accepted    trace: pass
  ...
gate calibrate: GS 1.000 (mutant 1.000 3/3, seeded 1.000 3/3), GSp 1.000 (3/3 correct)
```

Exit 0 means calibrated; 1 means it ran and failed (a bug no gate caught, a correct
implementation a gate rejected, or GS below `--min-gs`); 3 means it did not calibrate —
a gate could not run, or there are fewer than three decidable correct implementations.
An undecidable entry is excluded from the rate and listed, never counted as a catch.

## What this corpus does not do

- It is a fixture-scale corpus, not a study corpus: nine entries in one task. LA4's
  Phase 1 criterion also covers the MCY mutant set for every study task.
- The `trace` gate is the only visible gate here, because this fixture has no law package
  and so no `*.sby` job. A corpus whose task has proofs adds `formal` to `gates`.
- The mutants are hand-written in the catalogue's spirit, not generated by `law mutate`,
  which mutates the Bend model rather than the RTL.
